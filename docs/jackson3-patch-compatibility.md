# Jackson streaming-core patch qualification

This page records local qualification. See the [pull request's CI results](https://github.com/ym0506/routecontract/pull/92/checks)
for remote validation. This document does not announce a release or establish
external adoption.

## Reason for the change

Jackson streaming core 3.1.6 is a patch of the current 3.1.5 dependency.
The [upstream release notes](https://github.com/FasterXML/jackson/wiki/Jackson-Release-3.1.6)
include an asynchronous single-feed document-length guard, incremental
Reader-based field-name limits, and a buffered filtering-context correction.
RouteContract's `ManifestCodec` bounds input to 1 MiB before parsing a byte
array. Its InputStream overload reads at most that limit plus one byte before
rejecting oversized input. Its JSON writers use ordinary UTF-8 generators.
The affected Reader, nonblocking and buffered filtering paths were not found
in these application call sites. This is a dependency patch qualification,
not a reproduced RouteContract exploit or a claim that all vulnerabilities
are absent. Jackson databind advisories do not describe this streaming-only
runtime dependency.

## Acceptance criteria

- The library and current MySQL fixture resolve streaming core and its BOM
  at 3.1.6, while retaining the qualified Jackson 2.18.10 compatibility graph.
- Existing manifest canonicalization, validation and execution-budget tests
  pass. Real ShardingSphere-JDBC 5.5.3/MySQL tests pass on Java 17 and Java 21.
- Dependency locks are regenerated by Gradle. Each new verification entry
  matches a separate HTTPS Maven Central download. Ordinary strict verification
  passes without checksum-writing or lock-writing flags.
- A same-checkout Maven publication is consumed as a JAR by the standalone
  real-MySQL test. Its generated POM has only TTL 2.14.2 and streaming core
  3.1.6 as direct runtime dependencies. All official CycloneDX reports validate.
- Current-source inventory and generated-report inputs describe 3.1.6.
  Historical evidence and immutable public-release fixtures retain their
  original dependency identities. The independent public 0.1.3 first-project
  installation checks continue to exercise the released artifact.

## Publication boundary

The root source version remains 0.1.3 during this qualification. Any locally
generated POM/JAR is confined to a temporary repository for same-checkout
packaging checks. It is not the immutable Maven Central 0.1.3 publication,
whose POM declares streaming core 3.1.5. No artifact is uploaded or replaced.
Publishing this dependency change requires a new RouteContract release.

The standalone generated-publication fixture follows the current source's
locked third-party graph. Running a public 0.1.3 JAR with that fixture would
qualify the fixture's patched runtime, not the original release dependency
selection. Use `examples/first-project` for the public installation path.

## Qualification results

`verified - MySQL` and `verified - ShardingSphere-JDBC 5.5.3`: on macOS with
Gradle 9.7.1 and Homebrew OpenJDK 17.0.15 / 21.0.11, each JDK passes 48 core
tests and 14 real-MySQL tests with no failures, errors or skips. The MySQL image
is 8.4.11 pinned at
`sha256:b3b90af2a6552ae30c266fdb7d5dd55f3afb72404bb78d37fe8a23eb857fd3fb`.
This is one qualification run per JDK, not a performance or production-load
experiment. The existing tests include canonical encoding, strict duplicate
and unknown-field rejection, oversized-output rejection, tampered counts,
execution-budget failures, operation correlation and failure boundaries.

With JDK 17 in `JAVA_HOME` and on `PATH`:

```sh
./gradlew --no-daemon --no-build-cache --no-configuration-cache \
  --dependency-verification=strict clean check assemble \
  validateOfficialCycloneDxSbom \
  :routecontract-shardingsphere-5.5:generatePomFileForMavenJavaPublication
./gradlew --no-daemon --no-build-cache --no-configuration-cache \
  --dependency-verification=strict --rerun-tasks \
  -ProutecontractTestJavaVersion=21 \
  -Porg.gradle.java.installations.paths=/absolute/jdk17,/absolute/jdk21 \
  :routecontract-shardingsphere-5.5:test :mysql-example:test
./scripts/verify-standalone-consumer.sh
```

The first command validates all six official CycloneDX documents. The generated
POM contains exactly the two runtime dependencies in the acceptance criteria.
The standalone command passes its real-MySQL test with automatic SPI discovery
and one observed physical JDBC execution attempt, using a JAR from a temporary
same-checkout Maven publication. It uses ordinary strict dependency verification,
including a dependency refresh, without lock- or checksum-writing flags.

Raw JUnit results are emitted under
`routecontract-shardingsphere-5.5/build/test-results/test/`,
`examples/mysql/build/test-results/test/` and
`examples/standalone-consumer/build/test-results/test/`. Copy the first two
directories between the JDK runs to retain each environment's evidence.
The generated POM is
`routecontract-shardingsphere-5.5/build/publications/mavenJava/pom-default.xml`;
validated SBOMs are under `build/reports/verified-sbom/`.

The standalone test also passes once with the immutable public 0.1.3 JAR and
this fixture's patched runtime. Before that test, the actual resolved JARs were
checked against SHA-256
`9e883e618eb09d9ecf30814151bb4b0a43eba02c78d288cc582fa7e57e6edba2`
for RouteContract and
`d4938937b819b48f273a25929dc4fbc72ac03b0753c9c6398f54c3905caf7d0e`
for streaming core 3.1.6. The real-MySQL check is reproducible with:

```sh
./gradlew --no-daemon --no-build-cache --no-configuration-cache \
  --dependency-verification=strict -p examples/standalone-consumer \
  -ProutecontractGroup=io.github.ym0506.routecontract \
  -ProutecontractVersion=0.1.3 \
  -ProutecontractRepository=https://repo.maven.apache.org/maven2 clean test
```

This combination is distinct from the public release's original dependency
selection and from the same-checkout publication. The 329 submission packaging
tests also pass after the current-source inventory update.

The version-only change first failed before tests because strict locks still
selected 3.1.5. Gradle then regenerated the three affected lockfiles. All five
unique new metadata/JAR files were independently downloaded over HTTPS from
Maven Central and matched against the generated SHA-256 entries. Existing
verification entries, trust configuration and the 1.3 metadata schema were
preserved. Only core and its BOM change in the selected dependency locks.

independent public 0.1.3 first-project matrix is separate from the local
candidate qualification above. These results do not establish additional
ShardingSphere versions, arbitrary deserialization safety or external use.
