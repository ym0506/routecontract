# ShardingSphere Agent comparison — acceptance specification

Written before the replacement experiment implementation. This is opt-in research for [issue 14](https://github.com/ym0506/routecontract/issues/14), separate from RouteContract product modules and release artifacts.

1. Use released RouteContract 0.1.3, exact ShardingSphere-JDBC/Agent 5.5.3, Java 17, datasource-proxy 1.11.0, and two disposable MySQL containers with the existing pinned image digest. Keep product APIs, existing tests, and release allowlists unchanged.
2. Fetch the official ASF Agent archive and verify its published SHA-512 before extracting or running it. Attach the Agent only to a dedicated JUnit JVM; never instrument Maven/Gradle or use JAVA_TOOL_OPTIONS.
3. Run 20 named operations. Each operation performs one equality read and a same-value range read. Assert the complete returned row `(201, 3, PAID)` for both. datasource-proxy must independently observe one and two physical callbacks; RouteContract must capture the same three hook-reported attempts with complete normal-success outcomes and one stable signature across repetitions.
4. Hold each pair of physical fan-out calls at a bounded two-party barrier. Record 20 completed barriers so physical overlap is measured, not inferred from caller concurrency.
5. Receive Agent Zipkin exports only at 127.0.0.1 with bounded request count, body size, decompressed size, total memory, and worker count. Use always-on sampling and an exporter queue larger than the expected span count.
6. Keep raw telemetry, SQL, bind values, endpoint identities, trace IDs, and raw data-source names in memory only. Capture JVM stdout/stderr in bounded memory and do not generate raw JUnit report files. Publish only counts, reviewed aliases, classifications, versions, archive checksum, and a sanitized JUnit outcome derived from the actual console result.
7. Require 40 root statements with classified execute children, unique trace/span identities, valid parent links and normal-success status. Every equality root must have one child. Classify every fan-out root by its measured child count (one or two), without asserting in advance which outcome the Agent must produce. Reject unclassified, missing, duplicate, or orphan spans. Report per-root cardinality, not just a global total.
8. Unit-test the classifier with full 1-to-2 coverage and reduced fan-out coverage, plus missing-root, duplicate, orphan, incomplete control, and wrong-status controls. Test receiver size limits and compressed-body limits. These are synthetic controls, not native Agent results.
9. Run a dedicated manual, non-required Ubuntu/Java 17/MySQL workflow before promoting results to public comparison evidence. Bind safe results to the tested commit and an immutable workflow run/artifact. No external-user, performance, cross-version, batch, transaction, or arbitrary-async claim.
10. Document the additional Agent-only contract work: selecting/relating root and child spans to operations, minimization, alias mapping, deterministic normalization, baseline storage, and assertions. Generic Agent/OTel tooling can implement a comparable contract; RouteContract's proposed value is its ShardingSphere-specific packaging.

Before an immutable workflow result exists, measured local output remains author-run local evidence. Historical closed PRs 15/17 are source references only, not the result of this replacement experiment.
